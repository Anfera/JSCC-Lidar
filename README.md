# Joint Source–Channel Coding for Diffusion-Based LiDAR Denoising and Super-Resolution Over Noisy Channels

Reference implementation for the IEEE paper *"Joint Source–Channel Coding for
Diffusion-Based LiDAR Denoising and Super-Resolution Over Noisy Channels"*
(Ramirez-Jaime *et al.*; manuscript: [`bare_jrnl.tex`](bare_jrnl.tex)).

A 3-D convolutional JSCC autoencoder is trained against the **expected clean
photon-count tensor** Λ (the surrogate target), transmitted over a simulated
power-constrained AWGN channel, and decoded into a conditioning input for a
**frozen diffusion posterior sampler** that performs joint denoising and
super-resolution of HyperHeight Data Cubes (HHDCs).

## Environment

Python **3.9** (the author uses a conda environment).

```bash
# 1. PyTorch matching your CUDA toolkit, e.g. CUDA 12.1:
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
# 2. Everything else:
pip install -r requirements.txt
```

A CUDA GPU is required for the diffusion workflows (2 and 3). The 250-step
guided sampler is memory-heavy; `jscc_sweep.py` prints CUDA allocation as it
runs. Plan for a ≥24 GB GPU.

## Required artifacts (not in version control)

These are large binaries excluded by `.gitignore`. Place them at the exact
paths below before running the corresponding workflow.

| Artifact | Path | Size | Needed by |
|---|---|---|---|
| Diffusion prior | `prior/model2.pt` (from [`anfera236/HHDC-2m`](https://huggingface.co/anfera236/HHDC-2m)) | ~22 GB | Workflows 2, 3 |
| JSCC AE weights | `autoencoder_lambda/best_val_model_compression_{4,8,16}.pt` | ~150 MB each | Workflows 2, 3 |
| GT test cubes | `TestCube/southeast.npy`, `TestCube/pacific_sw.npy` | ~40 MB each | Workflows 2, 3 |
| Training dataset | HuggingFace `anfera236/HHDC` | — | Workflow 1 |

Notes:

- **Diffusion prior download.** Get the prior checkpoint from the HuggingFace
  repo <https://huggingface.co/anfera236/HHDC-2m> and place it at
  `prior/model2.pt`. `Trainer` loads `prior/model{resolution}.pt` and all
  inference scripts use `resolution = 2`, so the filename **must** be
  `prior/model2.pt` (rename on download if needed). E.g.:
  ```bash
  mkdir -p prior
  huggingface-cli download anfera236/HHDC-2m --local-dir prior
  # ensure the checkpoint ends up as prior/model2.pt
  ```
- **The prior's *training* dataset is NOT required to reproduce results.**
  `LectorCubos` (in `denoising_diffusion_pytorch/datasetsAndres.py`) silently
  tolerates a missing `./Dataset/DataOut2metro`; only the frozen
  `prior/model2.pt` checkpoint is needed for sampling.
- **Checkpoint ↔ paper compression ratio.** The code's integer
  `compression_ratio` is the inverse of the paper's bandwidth ratio ρ:

  | `compression_ratio` | paper ρ = k/m |
  |---|---|
  | 4  | 1/4  |
  | 8  | 1/8  |
  | 16 | 1/16 |

  `best_val_model_compression_32.pt` (ρ = 1/32) and the `best_train_*`
  variants are extra checkpoints not reported in the paper.
- The HuggingFace dataset is auto-downloaded into `hf_cache/` (the scripts set
  `HF_HOME=./hf_cache`).

## Workflows

Run every command **from the repository root** (all paths are relative to it).

### Workflow 1 — Train the JSCC autoencoder

```bash
# 1a. Cache the surrogate target Λ for the train/validation splits.
#     Downloads the HF dataset into ./hf_cache and writes ./lambda_cache/.
python precompute_lambda.py

# 1b. Train one autoencoder per compression ratio (separate model each).
#     Uses HuggingFace Accelerate (bf16) and the 'spawn' start method.
python train_autoencoder.py --compression_ratio 16   # ρ = 1/16
python train_autoencoder.py --compression_ratio 8    # ρ = 1/8
python train_autoencoder.py --compression_ratio 4    # ρ = 1/4
```

Checkpoints are written to `autoencoder_lambda/best_val_model_compression_<ratio>.pt`
and training auto-resumes from an existing best-val checkpoint.

### Workflow 2 — Single inference (one test scene)

```bash
# 2a. AE encode/transmit/decode a test cube -> TestCube/reconstructionFL.npy
#     Edit CONFIG["compression_ratio"] in run_autoencoder.py to pick the model.
python run_autoencoder.py

# 2b. Diffusion posterior sampling on that AE output; prints SSIM/PSNR/MAE
#     and shows CHM/DTM/profile figures.
python inferencia.py
```

`inferencia.py` toggles at the top: `USE_AUTOENCODER_OUTPUT` (consume the
Workflow-2a output), `USE_OPTIMAL_CUBE` (oracle Λ), and `LR_MULTIPLIER` (the
DPS guidance weight γ — see `find_lr_multiplier.py` and `lr_search_results.csv`
for calibrated values).

### Workflow 3 — Full sweep (paper figures/tables)

```bash
# Set COMPRESSION_RATIO at the top of jscc_sweep.py (4, 8, or 16),
# then run. Iterates CSNR x NUM_RUNS, writing one folder per (CR, CSNR, run).
python jscc_sweep.py
```

Output: `resultCubes/CR<ratio>_CSNR<csnr>/run<NN>/{recon.npz, results.png,
metrics.json}`. The sweep is **resumable** — completed `(CR, CSNR, run)` cells
(those with a `metrics.json`) are skipped on rerun.

## Known config notes

- **Channel-SNR range drift.** `train_autoencoder.py` and `jscc_sweep.py` use
  `channel_snr_db_range = (-5, 20)` (and `jscc_sweep.py` sweeps
  `CSNR ∈ [-5, 20]`), whereas `run_autoencoder.py` / `inferencia.py` use
  `(0, 20)` and the paper reports training/evaluation over **0–20 dB**. The
  *shipped* `autoencoder_lambda/` checkpoints were trained with `(-5, 20)`; the
  extra negative-SNR span only affects training-time SNR sampling and the
  FiLM conditioning, not the architecture or checkpoint loading. The range is
  left as-is so the provided weights are not misrepresented. To match the paper
  exactly, retrain with `channel_snr_db_range = (0, 20)` and restrict the
  sweep to `CSNR_RANGE = range(0, 21)`.
- **`forward_model.py` demo block.** Running `python forward_model.py`
  directly executes a `__main__` self-test that loads a non-shipped
  `TestCube/hhdc_casals_resampled.npy`; it is unused by the three workflows.
  Import `LidarForwardImagingModel` from it instead of executing the file.
